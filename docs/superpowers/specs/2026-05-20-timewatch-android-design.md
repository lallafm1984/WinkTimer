# Wink Timer Android 앱 설계

작성일: 2026-05-20
수정일: 2026-05-25
상태: 제품 포지셔닝 정정 반영 초안

## 1. 제품 방향

**Wink Timer**는 Android 우선의 일반 타이머 앱이다. 제품의 기본 컨셉은 집중 타이머가 아니라, 누구나 바로 사용할 수 있는 일반 타이머다.

제품의 핵심 메시지는 다음과 같다.

> 평범한 타이머에 룩, 윙크, 플립 컨트롤을 더한다.

따라서 앱 전체를 `집중 타이머`, `공부 타이머`, `디지털 웰빙 앱`으로 정의하지 않는다. 공부, 집중, 요리, 운동, 발표, 접근성, 손을 쓰기 어려운 상황은 사용 사례다. 제품 카테고리는 일반 타이머다.

차별점은 기존 타이머 앱에서 보기 어려운 카메라/센서 기반 조작이다.

- LOOK PAUSE: 화면을 보는지 감지해 타이머를 멈추거나 다시 흐르게 한다.
- WINK CONTROL: 윙크 동작으로 타이머 액션을 제어한다.
- FLIP TIMER: 기기를 뒤집는 자세로 타이머를 제어한다.

## 2. MVP 범위

MVP의 기준 모드는 **BASIC TIMER**다. BASIC TIMER는 카메라 권한 없이도 사용할 수 있어야 하며, 앱의 기본 무료 경험으로 남긴다.

MVP 주요 모드:

- BASIC TIMER: 버튼으로 시작, 일시정지, 재개, 리셋, 랩을 조작하는 일반 타이머
- LOOK PAUSE: 전면 카메라로 화면 응시 여부를 감지해 타이머를 멈추거나 재개하는 모드
- WINK CONTROL: 윙크로 시작, 일시정지, 재개, 랩, 리셋 등 일부 액션을 조작하는 모드
- FLIP TIMER: 기기 방향으로 시작, 일시정지, 재개를 조작하는 모드

타이머 방식:

- 스톱워치 방식: 목표 없이 시간이 계속 쌓인다.
- 목표 시간 방식: 사용자가 25분, 50분 같은 목표 시간을 설정할 수 있다.

MVP에 포함되는 기능:

- 첫 실행 온보딩
- BASIC TIMER 기본 사용
- 로컬 카메라 권한 요청
- LOOK/WINK 감지 테스트
- 타이머 화면
- 선택적 목표 시간 설정
- 감지 민감도 설정
- 감지 상태 표시 방식 설정
- 세션 요약
- 로컬 세션 기록
- FLIP TIMER용 기기 자세 감지

MVP에서 제외하는 기능:

- 사용자 계정
- 클라우드 동기화
- 소셜 기능
- 랭킹
- 주간 디지털 웰빙 리포트
- 상세 시선 이벤트 로그
- 카메라 영상, 이미지, 프레임 저장

## 3. 기술 방향

앱은 React Native UI와 Android 네이티브 감지 엔진으로 구성한다.

React Native가 담당하는 영역:

- 내비게이션
- 온보딩
- 타이머 UI
- 모드 선택 UI
- 설정 UI
- 세션 요약 UI
- 로컬 세션 기록 UI
- 로컬 저장소 연동

Android 네이티브 감지 엔진이 담당하는 영역:

- 전면 카메라 접근
- 프레임 분석
- 얼굴 감지
- 얼굴 방향과 눈 상태 해석
- 화면 응시 상태 분류
- 윙크 상태 분류
- 기기 자세 감지
- 네이티브에서 JavaScript로 상태 이벤트 전달

네이티브 엔진은 JavaScript로 가벼운 상태값만 전달한다.

- `looking`
- `notLooking`
- `unknown`
- 눈 상태와 윙크 방향
- 기기 자세
- 신뢰도 점수
- 타임스탬프

카메라 프레임, 얼굴 이미지, 원본 감지 산출물은 JavaScript로 전달하지 않고 저장하지 않는다.

예상 Android 기술 스택:

- Kotlin 네이티브 모듈
- CameraX 또는 선택한 React Native 카메라 라이브러리에 맞는 카메라 백엔드
- 온디바이스 ML Kit 얼굴 감지 또는 동급의 로컬 얼굴 분석 API
- Android 센서 기반 기기 자세 감지
- 프로젝트 구성에 맞는 React Native 이벤트 브리지 또는 TurboModule 호환 인터페이스

첫 구현은 Android 전용으로 진행한다. iOS는 Android에서 핵심 경험과 감지 안정성을 검증한 뒤 검토한다.

## 4. 모드별 동작

### 4.1 BASIC TIMER

BASIC TIMER는 앱의 기준 경험이다.

- 카메라 권한이 필요 없다.
- 모든 기본 타이머 액션은 버튼으로 동작한다.
- 광고/과금 설계에서 무료 기본 모드로 취급한다.

### 4.2 LOOK PAUSE

LOOK PAUSE는 완전한 eye tracking을 목표로 하지 않는다. 다음 신호를 조합해 사용자가 화면을 보고 있는지 추정한다.

- 얼굴 존재 여부
- 얼굴 각도
- 사용 가능한 경우 눈 뜸 확률
- 감지 신뢰도
- 최근 감지 상태의 안정성

감지 상태는 세 가지다.

- `notLooking`: 모드 규칙에 따라 타이머가 흐를 수 있다.
- `looking`: 모드 규칙에 따라 타이머가 멈출 수 있다.
- `unknown`: 감지가 불가능하거나 불안정하다.

LOOK PAUSE의 기본 반응은 짧은 유예 후 정지다. 순간적인 시선 이동이나 불안정한 감지 때문에 타이머가 바로 끊기는 것을 줄이기 위해서다.

### 4.3 WINK CONTROL

WINK CONTROL은 윙크를 타이머 조작 입력으로 사용한다.

- 단일 윙크는 정확도 검증 전까지 Beta로 취급한다.
- 리셋은 실수 방지를 위해 단일 윙크보다 윙크 홀드 또는 버튼이 우선이다.
- 좌/우 윙크 방향은 내부 감지 좌표와 사용자 시점 표시가 다를 수 있으므로 UI 문구를 일관되게 유지해야 한다.

### 4.4 FLIP TIMER

FLIP TIMER는 기기 자세를 타이머 조작 입력으로 사용한다.

- 기기를 엎으면 시작 또는 재개한다.
- 기기를 위로 향하게 두면 일시정지한다.
- 리셋은 버튼으로 유지한다.
- 카메라 권한이 필요 없다.

## 5. 프라이버시 설계

프라이버시는 MVP의 일부다.

앱은 다음 내용을 명확히 안내해야 한다.

- BASIC TIMER는 카메라 없이 사용할 수 있다.
- 카메라 분석은 LOOK/WINK 관련 기능에서만 사용된다.
- 카메라 분석은 기기 안에서만 처리된다.
- 영상은 녹화되지 않는다.
- 이미지는 저장되지 않는다.
- 얼굴 데이터는 업로드되지 않는다.
- 상세 시선 이벤트 로그는 저장되지 않는다.
- 카메라는 감지 세션과 감지 테스트 화면에서만 사용된다.

타이머 화면에는 카메라 프리뷰를 보여주지 않는다. 작은 감지 상태 표시만 제공한다.

셀프뷰는 초기 설정, 감지 테스트, 캘리브레이션 성격의 설정 화면에서만 보여준다. 사용자가 카메라 권한을 거부하거나 감지가 불가능한 경우에는 BASIC TIMER와 FLIP TIMER처럼 카메라가 필요 없는 모드를 제공한다.

## 6. 사용자 흐름

### 6.1 첫 실행

첫 실행 흐름은 다음 순서로 진행한다.

1. Wink Timer가 일반 타이머이며 추가 제스처 모드를 제공한다는 설명
2. BASIC TIMER는 카메라 없이 사용 가능하다는 안내
3. LOOK/WINK 기능을 위한 프라이버시 설명
4. 필요 시 카메라 권한 요청
5. 임시 셀프뷰가 포함된 감지 테스트
6. 타이머 홈 진입

온보딩은 카메라 권한을 강제하지 않는다. 사용자는 BASIC TIMER부터 시작할 수 있어야 한다.

### 6.2 타이머 세션

타이머 홈 화면은 다음 요소를 포함한다.

- 큰 타이머 표시
- 현재 모드명
- 시작, 일시정지, 재개, 종료 컨트롤
- 선택적 목표 시간 설정
- 현재 모드의 조작 힌트
- 작은 감지 상태 표시
- 설정과 기록 진입점

세션 중 동작:

- BASIC TIMER에서는 버튼 입력으로 시간이 흐르고 멈춘다.
- LOOK PAUSE에서는 `notLooking`/`looking` 상태가 모드 규칙에 따라 타이머 흐름을 제어한다.
- WINK CONTROL에서는 윙크가 모드 규칙에 따라 타이머 액션을 실행한다.
- FLIP TIMER에서는 기기 자세가 모드 규칙에 따라 타이머 흐름을 제어한다.
- 앱이 백그라운드로 가거나 화면이 꺼질 때의 처리 방식은 모드별 안정성을 기준으로 정한다.

### 6.3 세션 종료

세션 종료 후 요약 화면을 보여준다.

- 기록된 타이머 시간
- 사용 모드
- LOOK PAUSE를 사용한 경우 멈춘 총 시간
- 멈춘 횟수
- 랩 기록
- 목표 시간을 사용한 경우 목표 시간
- 목표 시간을 사용한 경우 달성 여부

사용자는 타이머 홈으로 돌아가거나 세션 기록을 볼 수 있다.

## 7. 화면

### 7.1 온보딩

목적: 앱이 일반 타이머이며, 룩/윙크/플립 모드는 추가 조작 방식이라는 점을 설명한다.

주요 내용:

- 앱이 하는 일
- BASIC TIMER가 카메라 없이 동작한다는 점
- 카메라 권한이 필요한 기능
- 저장하거나 업로드하지 않는 데이터
- 감지 테스트 진입

### 7.2 타이머 홈

목적: 사용자가 일반 타이머를 빠르게 시작하고, 필요할 때 부가 모드로 전환할 수 있게 한다.

주요 요소:

- 큰 타이머
- 현재 모드명
- 시작, 일시정지, 재개, 종료 컨트롤
- 선택적 목표 시간
- 최소한의 감지 상태 표시
- 설정과 기록 진입점

기본 감지 상태 표시는 아이콘 또는 점 기반이다. 사용자는 접근성이나 이해를 위해 `감지 중`, `일시정지`, `카메라 사용 불가`, `윙크 인식` 같은 짧은 텍스트 표시를 켤 수 있다.

### 7.3 세션 요약

목적: 세션 종료 직후 사용자에게 최소한의 기록 가치를 제공한다.

주요 요소:

- 기록된 타이머 시간
- 사용 모드
- 멈춘 시간
- 멈춘 횟수
- 랩 기록
- 목표 달성 여부

### 7.4 세션 기록

목적: 저장된 세션 요약을 확인한다.

MVP의 기록 화면은 날짜순 목록이다. 일별 또는 주간 그래프는 향후 분석 기능으로 남긴다.

### 7.5 설정과 감지 테스트

목적: 감지 동작을 조정하고 카메라/센서 설정 문제를 확인한다.

주요 요소:

- 룩 감지 민감도 프리셋
- 윙크 캘리브레이션
- 감지 상태 표시 방식
- 카메라 권한 상태
- 임시 셀프뷰가 포함된 감지 테스트
- 기기 자세 감지 테스트

## 8. 로컬 데이터 모델

MVP는 세션 요약만 로컬에 저장한다. 향후 동기화를 추가하더라도 핵심 의미가 바뀌지 않도록 명확한 구조로 둔다.

세션 요약 필드:

- `id`
- `startedAt`
- `endedAt`
- `focusDurationMs`
- `lookPausedDurationMs`
- `lookPauseCount`
- `targetEnabled`
- `targetDurationMs`
- `targetCompleted`
- `sensitivity`
- `normalTimerMode`
- `timerModeId`

현재 코드의 `focusDurationMs` 명칭은 역사적 구현명이다. 제품 문구에서는 `기록된 타이머 시간`, `경과 시간`, `타이머 시간`으로 표현한다. 코드 리네임은 별도 리팩터링으로 다룬다.

저장하지 않는 데이터:

- 카메라 영상
- 카메라 이미지
- 원본 프레임
- 얼굴 이미지
- 상세 시선 또는 응시 이벤트 타임라인

## 9. 오류 처리

카메라 권한 거부:

- LOOK/WINK 기능에는 카메라 권한이 필요하다고 설명한다.
- BASIC TIMER와 FLIP TIMER처럼 카메라가 필요 없는 모드를 제공한다.
- 시스템 설정으로 이동할 수 있게 한다.

감지 불가:

- 불안감을 주지 않는 상태 표시를 제공한다.
- LOOK/WINK 모드의 카메라 조작이 불안정할 수 있음을 설명한다.
- 감지 테스트와 민감도 조정 경로를 제공한다.

앱 백그라운드 이동 또는 화면 꺼짐:

- 모드별로 예측 가능한 동작을 제공한다.
- 앱 복귀 시 현재 상태를 명확히 보여준다.

낮은 신뢰도 또는 어두운 조명:

- `unknown`으로 분류한다.
- LOOK/WINK 조작을 보수적으로 처리한다.
- 설정 화면에서 감지 테스트를 실행할 수 있게 한다.

## 10. 수익화 방향

수익화 설계의 기준:

- BASIC TIMER는 무료 기본 경험이다.
- LOOK/WINK/FLIP은 광고 보상 또는 유료 잠금 해제 대상이 될 수 있는 부가 모드다.
- 유료 상품은 단순 `광고 제거`보다 `부가 모드 잠금 해제 + 광고 제거`로 포지셔닝하는 편이 적합하다.
- 타이머 실행 중 광고는 사용성 훼손 가능성이 높으므로 피한다.

## 11. 향후 확장

MVP 이후 확장 후보:

- 커스텀 제스처 매핑
- 고급 윙크 캘리브레이션
- 다양한 타이머 프리셋
- 접근성/핸즈프리 사용 사례 강화
- 일별, 주간 사용 기록
- 클라우드 동기화
- iOS 구현

향후 모드는 가능한 한 같은 감지 엔진과 세션 모델을 재사용한다. 모드 시스템은 다음 값을 정의하는 구조가 적합하다.

- 타이머 방식
- 입력 방식
- 모드별 반응 규칙
- 요약 지표
- 시각적 상태 표시 방식

## 12. 성공 기준

MVP가 성공했다고 판단하는 기준:

1. BASIC TIMER가 카메라 없이 일반 타이머로 자연스럽게 동작한다.
2. 신규 사용자가 1분 안에 기본 타이머를 시작하고 모드를 이해할 수 있다.
3. LOOK/WINK/FLIP 모드가 앱의 차별점으로 명확히 느껴진다.
4. 카메라 프리뷰 없이도 현재 모드의 조작 방식이 명확하다.
5. 프라이버시 안내와 실제 구현이 일치한다.
6. 사용자가 앱을 집중 전용 타이머가 아니라 기능이 확장된 일반 타이머로 이해한다.

## 13. 구현 계획 단계에서 결정할 항목

다음 항목은 구현 계획 단계에서 결정한다.

- 정확한 React Native 프로젝트 구성
- Bare React Native, Expo prebuild, 기타 워크플로 중 선택
- 사용할 카메라 라이브러리
- 기존 브리지 또는 New Architecture 우선 적용 여부
- 로컬 저장소 기술
- 테스트 대상 Android 기기 목록
- 코드 내 `focusDurationMs` 명칭을 유지할지, 제품 포지션에 맞춰 리네임할지

이 항목들은 제품 설계의 차단 요소가 아니라 구현 전략 결정 사항이다.
