# 타임워치 Android 앱 설계

작성일: 2026-05-20
상태: 사용자 검토용 초안

## 1. 제품 방향

타임워치는 사용자가 앱을 쳐다보지 않을 때만 시간이 흐르는 Android 우선 집중 타이머 앱이다. 제품의 핵심 메시지는 다음과 같다.

> 폰을 보지 않는 시간이 곧 집중 시간이다.

첫 버전은 하나의 명확한 사용 루프에 집중한다. 사용자는 집중 세션을 시작하고, 화면을 보지 않으며, 세션 종료 후 요약을 확인한다. 향후 디지털 웰빙 리포트, 챌린지, 다양한 콘텐츠 모드로 확장할 수 있어야 하지만, MVP에서는 집중 모드 하나만 제공한다.

초기 타깃 사용자는 공부하는 학생, 수험생, 그리고 무의식적인 스마트폰 확인 습관을 줄이고 싶은 디지털 웰빙 사용자다.

## 2. MVP 범위

MVP의 주요 모드는 집중 모드 하나다.

집중 모드는 두 가지 타이머 방식을 지원한다.

- 스톱워치 방식: 목표 없이 집중 시간이 계속 쌓인다.
- 목표 시간 방식: 사용자가 25분, 50분 같은 목표 시간을 설정할 수 있다.

세션 중 전면 카메라는 사용자가 앱을 보고 있는지 로컬에서 분석한다. 사용자가 화면을 보지 않는 것으로 판단되면 타이머가 흐르고, 화면을 보고 있는 것으로 판단되면 현재 반응 규칙에 따라 타이머가 멈춘다.

MVP에 포함되는 기능:

- 첫 실행 온보딩
- 로컬 카메라 권한 요청
- 감지 테스트
- 집중 타이머 화면
- 선택적 목표 시간 설정
- 감지 민감도 설정
- 감지 상태 표시 방식 설정
- 세션 요약
- 로컬 세션 기록
- 카메라 없는 일반 타이머 모드

MVP에서 제외하는 기능:

- 사용자 계정
- 클라우드 동기화
- 소셜 기능
- 랭킹
- 주간 디지털 웰빙 리포트
- 여러 콘텐츠 모드
- 상세 시선 이벤트 로그
- 카메라 영상, 이미지, 프레임 저장

## 3. 기술 방향

앱은 React Native UI와 Android 네이티브 감지 엔진으로 구성한다.

React Native가 담당하는 영역:

- 내비게이션
- 온보딩
- 타이머 UI
- 설정 UI
- 세션 요약 UI
- 로컬 세션 기록 UI
- 로컬 저장소 연동

Android 네이티브 감지 엔진이 담당하는 영역:

- 전면 카메라 접근
- 프레임 분석
- 얼굴 감지
- 얼굴 방향과 눈 상태 해석
- 화면 응시 상태 분류
- 네이티브에서 JavaScript로 상태 이벤트 전달

네이티브 엔진은 JavaScript로 가벼운 상태값만 전달한다.

- `looking`
- `notLooking`
- `unknown`
- 신뢰도 점수
- 타임스탬프

카메라 프레임, 얼굴 이미지, 원본 감지 산출물은 JavaScript로 전달하지 않고 저장하지 않는다.

예상 Android 기술 스택:

- Kotlin 네이티브 모듈
- CameraX 또는 선택한 React Native 카메라 라이브러리에 맞는 카메라 백엔드
- 온디바이스 ML Kit 얼굴 감지 또는 동급의 로컬 얼굴 분석 API
- 프로젝트 구성에 맞는 React Native 이벤트 브리지 또는 TurboModule 호환 인터페이스

첫 구현은 Android 전용으로 진행한다. iOS는 Android에서 핵심 경험과 감지 안정성을 검증한 뒤 검토한다.

## 4. 감지 동작

MVP는 완전한 eye tracking을 목표로 하지 않는다. 대신 다음 신호를 조합해 사용자가 앱을 보고 있는지 추정한다.

- 얼굴 존재 여부
- 얼굴 각도
- 사용 가능한 경우 눈 뜸 확률
- 감지 신뢰도
- 최근 감지 상태의 안정성

감지 상태는 세 가지다.

- `notLooking`: 타이머가 흐를 수 있다.
- `looking`: 현재 규칙에 따라 타이머가 멈춰야 한다.
- `unknown`: 감지가 불가능하거나 불안정하다. 이 상태에서는 집중 시간이 조용히 쌓이면 안 된다.

민감도 프리셋:

- 느슨함: 얼굴 각도와 짧은 시선 이동에 관대하다.
- 보통: 기본값이다.
- 엄격함: 사용자가 화면을 본 것으로 더 쉽게 판단한다.

집중 모드의 기본 반응은 짧은 유예 후 정지다. 순간적인 시선 이동이나 불안정한 감지 때문에 타이머가 바로 끊기는 것을 줄이기 위해서다. 내부 구조는 향후 다음 반응 규칙을 추가할 수 있게 둔다.

- 즉시 정지
- 유예 후 정지
- 게이지 기반 정지

## 5. 프라이버시 설계

프라이버시는 MVP의 일부다.

앱은 다음 내용을 명확히 안내해야 한다.

- 카메라 분석은 기기 안에서만 처리된다.
- 영상은 녹화되지 않는다.
- 이미지는 저장되지 않는다.
- 얼굴 데이터는 업로드되지 않는다.
- 상세 시선 이벤트 로그는 저장되지 않는다.
- 카메라는 감지 세션과 감지 테스트 화면에서만 사용된다.

타이머 화면에는 카메라 프리뷰를 보여주지 않는다. 작은 감지 상태 표시만 제공한다.

셀프뷰는 초기 설정, 감지 테스트, 캘리브레이션 성격의 설정 화면에서만 보여준다. 사용자가 카메라 권한을 거부하거나 감지가 불가능한 경우에는 카메라 기반 정지 기능이 없는 일반 타이머 모드를 제공한다.

## 6. 사용자 흐름

### 6.1 첫 실행

첫 실행 흐름은 다음 순서로 진행한다.

1. 짧은 제품 설명
2. 프라이버시 설명
3. 카메라 권한 요청
4. 임시 셀프뷰가 포함된 감지 테스트
5. 타이머 홈 진입

온보딩 완료 후 기본 민감도는 보통이다.

### 6.2 타이머 세션

타이머 홈 화면은 다음 요소를 포함한다.

- 큰 타이머 표시
- 시작, 일시정지, 재개, 종료 컨트롤
- 선택적 목표 시간 설정
- 작은 감지 상태 표시
- 설정과 기록 진입점

세션 중 동작:

- 사용자가 `notLooking`으로 분류될 때만 타이머가 흐른다.
- 사용자가 `looking`으로 분류되고 현재 규칙의 기준을 넘으면 타이머가 멈춘다.
- 감지 상태가 `unknown`이면 집중 시간을 쌓지 않는다.
- 앱이 백그라운드로 가거나 화면이 꺼지면 세션은 자동 일시정지된다.
- 앱이 다시 전면으로 돌아오면 감지를 재개하고, 사용자가 세션을 이어갈 수 있게 한다.

### 6.3 세션 종료

세션 종료 후 요약 화면을 보여준다.

- 집중 시간
- 화면을 본 것으로 판단되어 멈춘 총 시간
- 멈춘 횟수
- 목표 시간을 사용한 경우 목표 시간
- 목표 시간을 사용한 경우 달성 여부

사용자는 타이머 홈으로 돌아가거나 세션 기록을 볼 수 있다.

## 7. 화면

### 7.1 온보딩

목적: 앱의 동작 방식과 프라이버시 원칙을 설명하고, 카메라 권한을 요청하며, 감지가 동작하는지 확인한다.

주요 내용:

- 앱이 하는 일
- 카메라 권한이 필요한 이유
- 저장하거나 업로드하지 않는 데이터
- 감지 테스트 진입

### 7.2 타이머 홈

목적: 사용자가 집중 세션을 시작하고 진행하는 메인 경험을 제공한다.

주요 요소:

- 큰 타이머
- 시작, 일시정지, 재개, 종료 컨트롤
- 선택적 목표 시간
- 최소한의 감지 상태 표시
- 설정과 기록 진입점

기본 감지 상태 표시는 아이콘 또는 점 기반이다. 사용자는 접근성이나 이해를 위해 `집중 중`, `감지 중`, `일시정지`, `카메라 사용 불가` 같은 짧은 텍스트 표시를 켤 수 있다.

### 7.3 세션 요약

목적: 세션 종료 직후 사용자에게 최소한의 회고 가치를 제공한다.

주요 요소:

- 집중 시간
- 멈춘 시간
- 멈춘 횟수
- 목표 달성 여부

### 7.4 세션 기록

목적: 저장된 세션 요약을 확인한다.

MVP의 기록 화면은 날짜순 목록이다. 일별 또는 주간 그래프는 향후 디지털 웰빙 기능으로 남긴다.

### 7.5 설정과 감지 테스트

목적: 감지 동작을 조정하고 카메라 설정 문제를 확인한다.

주요 요소:

- 민감도 프리셋
- 감지 상태 표시 방식
- 일반 타이머 모드 토글
- 카메라 권한 상태
- 임시 셀프뷰가 포함된 감지 테스트

## 8. 로컬 데이터 모델

MVP는 세션 요약만 로컬에 저장한다. 향후 동기화를 추가하더라도 핵심 의미가 바뀌지 않도록 명확한 구조로 둔다.

세션 요약 필드:

- `id`
- `startedAt`
- `endedAt`
- `focusDurationMs`
- `lookPausedDurationMs`
- `lookPauseCount`
- `targetEnabled`
- `targetDurationMs`
- `targetCompleted`
- `sensitivity`
- `normalTimerMode`

저장하지 않는 데이터:

- 카메라 영상
- 카메라 이미지
- 원본 프레임
- 얼굴 이미지
- 상세 시선 또는 응시 이벤트 타임라인

## 9. 오류 처리

카메라 권한 거부:

- 시선 기반 정지 기능에는 카메라 권한이 필요하다고 설명한다.
- 일반 타이머 모드를 제공한다.
- 시스템 설정으로 이동할 수 있게 한다.

감지 불가:

- 불안감을 주지 않는 상태 표시를 제공한다.
- 감지가 불안정한 동안 집중 시간을 쌓지 않는다.
- 감지 테스트와 민감도 조정 경로를 제공한다.

앱 백그라운드 이동 또는 화면 꺼짐:

- 세션을 자동 일시정지한다.
- 앱 복귀 시 현재 상태를 명확히 보여준다.

낮은 신뢰도 또는 어두운 조명:

- `unknown`으로 분류한다.
- 집중 시간을 조용히 쌓지 않는다.
- 설정 화면에서 감지 테스트를 실행할 수 있게 한다.

## 10. 향후 확장

MVP 이후 확장 후보:

- 디지털 웰빙 리포트
- 일별, 주간 집중 추세
- `10분 동안 화면 안 보기` 같은 챌린지 모드
- 명상 또는 휴식 모드
- 콘텐츠별 반응 규칙
- 클라우드 동기화
- iOS 구현

향후 모드는 가능한 한 같은 감지 엔진과 세션 모델을 재사용한다. 모드 시스템은 다음 값을 정의하는 구조가 적합하다.

- 타이머 방식
- 감지 반응 규칙
- 요약 지표
- 시각적 상태 표시 방식

## 11. 성공 기준

MVP가 성공했다고 판단하는 기준:

1. 주요 Android 기기에서 실제 집중 세션에 사용할 수 있을 정도로 감지가 안정적이다.
2. 신규 사용자가 1분 안에 세션을 이해하고 시작할 수 있다.
3. 타이머 중 카메라 프리뷰 없이도 `쳐다보면 멈춘다`는 동작이 명확하다.
4. 세션 요약이 사용자의 스마트폰 확인 습관을 돌아보게 하는 최소 가치를 제공한다.
5. 프라이버시 안내와 실제 구현이 일치한다.

## 12. 구현 계획 단계에서 결정할 항목

다음 항목은 구현 계획 단계에서 결정한다.

- 정확한 React Native 프로젝트 구성
- Bare React Native, Expo prebuild, 기타 워크플로 중 선택
- 사용할 카메라 라이브러리
- 기존 브리지 또는 New Architecture 우선 적용 여부
- 로컬 저장소 기술
- 테스트 대상 Android 기기 목록

이 항목들은 제품 설계의 차단 요소가 아니라 구현 전략 결정 사항이다.
